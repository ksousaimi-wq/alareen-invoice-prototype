# نموذج أولي — نظام التحقق من فواتير مقاولي الباطن وأرشفتها

**اتحاد العرين للمقاولات** · Al Areen Union Contracting Co.

نموذج واجهات قابل للنقر (عربي RTL) لمنصّة التحقق من فواتير مقاولي الباطن
ومطابقتها ببنود جداول الكميات المتعاقد عليها، وكشف الفواتير المكررة،
والتحقق من الالتزام الضريبي، وأرشفة المستندات.

### 🔗 العرض المباشر

**https://ksousaimi-wq.github.io/alareen-invoice-prototype/**

### ⚠️ هذا نموذج للعرض فقط

- **كل البيانات المعروضة مُختلَقة بالكامل** — لا توجد أي فواتير أو عقود أو
  أرقام ضريبية حقيقية، والأرقام الضريبية المعروضة غير مسجّلة لدى أي جهة.
- الأزرار تعمل للتنقّل والعرض فقط — **لا يُحفَظ أي شيء** ولا توجد قاعدة بيانات.
- الغرض منه مراجعة تصميم الشاشات وسير العمل قبل بدء التطوير الفعلي.

### كيفية الاستخدام

يعمل النموذج بلا إنترنت — ملف واحد مستقل بلا أي اعتماديات خارجية. يمكن فتح
الرابط أعلاه مباشرة، أو تنزيل `index.html` وفتحه بأي متصفح.

**في شاشة الدخول اختر الدور** (مدير / محاسب مراجع / مطّلع) — دور "مطّلع" يُخفي
عمداً كل أزرار التعديل، وهو ما يعكس الصلاحيات المخطط لها فعلياً.

### الفواتير التجريبية — كل نوع ملاحظة قابل للاستعراض

| الفاتورة | ما تعرضه |
|---|---|
| `INV-1041` | فاتورة نظيفة — معتمدة للدفع |
| `INV-1042` | فاتورة مكررة (تطابق تام + بصمة ملف متطابقة) |
| `INV-1055` | انحراف سعر الوحدة عن العقد (+٨٫٥٧٪) |
| `INV-1061` | تجاوز الكمية التعاقدية (٨٬٧٢٠ من أصل ٨٬٥٠٠ م³) |
| `INV-1068` | خطأ حسابي في بند + عدم تطابق المجاميع |
| `INV-2231` | رمز QR مفقود + رقم ضريبي غير مُتحقق منه |
| `INV-2245` | انجراف سعر تاريخي مقارنة بآخر فاتورة معتمدة |
| `INV-2260` | ثقة استخراج منخفضة — بانتظار المراجعة البشرية |
| `INV-3301` | رقم ضريبي بصيغة غير صحيحة + لا يوجد عقد مطابق |

### جرّب سير العمل بنفسك

الأزرار الأساسية تعمل فعلياً داخل النموذج (في الذاكرة فقط — تحديث الصفحة يُعيد البيانات التجريبية):

- افتح فاتورة مُعلَّمة ← تبويب **الملاحظات** ← اختر سبب المعالجة واكتب ملاحظة ← **قبول المعالجة**.
  لاحظ أن زر **اعتماد للدفع** يبقى معطّلاً حتى تُعالَج كل الملاحظات الحاجبة — هذه هي بوابة الدفع.
- في `INV-2231` افتح تبويب **التحقق الضريبي** وسجّل نتيجة الاستعلام لدى الهيئة.
- في `INV-1042` المكررة افتح **مقارنة بالفاتورة** وسجّل قرار التكرار.
- في `INV-2260` افتح **مراجعة الاستخراج** ثم **اعتماد الحقول وتشغيل التحقق**.
- كل إجراء يظهر فوراً في **سجل التدقيق** وفي تبويب **السجل** الخاص بالفاتورة.
- **عقد جديد ← أسقط مستند العقد**: اضغط "جرّب بمستند تجريبي" ليستخرج النظام رقم العقد والأطراف والقيمة والمدد ونسب
  المحتجز والدفعة المقدمة وجدول الكميات من عقد عربي، مع درجة ثقة لكل حقل وربطه بموضعه في المستند — عدّل ما تشاء ثم احفظ.
- زر الإجراء الرئيسي أعلى الشاشة يتغيّر حسب الصفحة: **عقد جديد** في العقود (معالج من ٣ خطوات مع جدول
  الكميات — استيراد من Excel أو إدخال يدوي)، **مقاول باطن جديد** (مع تحقق فوري من صيغة الرقم الضريبي)،
  **مشروع جديد**، **مستخدم جديد**. جرّب الدخول بدور "محاسب مراجع" لترى كيف تُعطَّل هذه الأزرار لغير المدير.

- **المشتريات**: افتح `PR-2026-019` وأكمل درجات التقييم الفني، ثم `PR-2026-018` لترى التقييم التجاري
  (عرض مستبعد فنياً رغم أنه الأرخص) والترسية وسلسلة الاعتماد وإصدار أمر الشراء. `PR-2026-021` يوضح
  قاعدة "٣ عروض كحد أدنى" — عرضان فقط فلا يمكن بدء التقييم. أو ابدأ **طلب شراء جديد** وامشِ الدورة كاملة.
- **طلب شراء جديد ← أسقط طلب المواد**: "جرّب بمستند تجريبي" يستخرج الموضوع والمشروع والبنود والكميات من نموذج
  طلب مواد ممسوح ضوئياً، ويجلب آخر سعر شراء لكل بند كسعر تقديري — راجع الصفوف المظلّلة ثم أرسل للاعتماد.

يعمل النموذج على الجوال أيضاً — القائمة تصبح درجاً جانبياً والشاشات تملأ العرض.

### الشاشات الأجدر بالمراجعة

- **مراجعة الاستخراج** — هل تطابق آلية المراجعة البشرية طريقة عمل المحاسبين فعلياً؟
- **تبويب الملاحظات** في أي فاتورة مُعلَّمة — هل أسباب المعالجة المتاحة هي الصحيحة؟
- **الكميات التراكمية** في تبويب البنود — هل هذه هي الطريقة المتبعة لتتبع الكميات المفوترة؟
